# dotfiles

Терминальное окружение для Go-разработки на macOS: zsh, tmux, Neovim,
iTerm2 и git-инструменты. Всё ПО ставится из Homebrew по `Brewfile`; в
репозитории только конфиги и скрипты.

## Быстрый старт

```sh
xcode-select --install            # git и компилятор C, если их ещё нет
# Homebrew: https://brew.sh

git clone <url-репозитория> ~/workspace/dotfiles   # путь любой
cd ~/workspace/dotfiles

./install.sh --dry-run            # что будет сделано; конфиги не меняются
./install.sh                      # установка
./install.sh --check              # проверка: ✓ / ✗ по каждому пункту
exec zsh
```

`install.sh` можно запускать повторно: сделанное пропускается. Всё, что
заменяется, сначала переносится в `~/.local/state/dotfiles/backup-<время>/`.
`sudo` не используется. Флаги: `--no-brew` (пакеты уже стоят),
`--skip-verify` (без проверок nvim).

## Что куда

| В репозитории | На машине |
|---|---|
| весь репозиторий | `~/.config/dotfiles` — ссылка, через неё ссылаются конфиги |
| `Brewfile` | `brew bundle --no-upgrade` |
| `zsh/zshrc.zsh` | строка `source ~/.config/dotfiles/zsh/zshrc.zsh` в конце `~/.zshrc` |
| `tmux/tmux.conf` | строка `source-file ~/.config/dotfiles/tmux/tmux.conf` в `~/.tmux.conf` |
| `tmux/dev`, `devlog`, `projects` | ссылки в `~/.local/bin` |
| `git/gitconfig` | `include.path` в `~/.gitconfig` |
| `git/lazygit.yml` | ссылка `~/Library/Application Support/lazygit/config.yml` |
| `iterm/go-backend.json` | копия в `~/Library/Application Support/iTerm2/DynamicProfiles/` |
| `nvim/` | ссылка `~/.config/nvim` |
| `nvim/tools/goindex` | собирается в `~/.local/share/nvim/change-tree/go-change-index` |

В `~/.zshrc`, `~/.tmux.conf` и `~/.gitconfig` добавляется по одной строке;
остальное их содержимое не трогается.

## Что скачивается из сети

- пакеты Homebrew из `Brewfile`;
- 17 плагинов Neovim — `git clone` с GitHub строго по коммитам из
  `nvim/nvim-pack-lock.json`;
- исходники парсеров Tree-sitter, которые собирает nvim-treesitter: Go
  (`go`, `gomod`, `gosum`, `gowork`), SQL (`sql`), контракты (`proto`) и
  теги в комментариях (`comment`).

AST-хелпер дерева правок собирается локально из `nvim/tools/goindex`: только
стандартная библиотека Go, `GOPROXY=off`, `GOTOOLCHAIN=local`.

Во время работы плагины и парсеры в сеть не ходят: только при установке и
при обновлении вручную. `install.sh` выключает статистику Homebrew
(`brew analytics off`) и телеметрию Go (`go telemetry off`). `~/go/bin` и
`~/.local/bin` стоят в конце `PATH`: поставленное через `go install` не
подменит одноимённую системную программу.

## Локальные настройки (не в репозитории)

- `~/.zshrc` **выше** строки dotfiles: прокси, `GOPRIVATE` / `GOPROXY` /
  `GONOSUMDB`, `DEV_PROJECT_ROOTS`, свои алиасы. Строка dotfiles должна
  оставаться последней: внутри неё в самом конце подключается
  zsh-syntax-highlighting.
- `~/.gitconfig`: `user.name`, `user.email`.
- `~/.config/dev/<проект>.zsh` — раскладки `dev` для своих проектов;
  `~/.config/dev/sets/<набор>` — наборы проектов для `dev -w`.

## Вручную после установки

`install.sh` в конце печатает то, что осталось:

- **git:** `git config --global user.name "…"`, `git config --global user.email "…"`.
- **delve** (отладка в nvim) требует режима разработчика macOS:
  `sudo DevToolsSecurity -enable && sudo dscl . append /Groups/_developer GroupMembership $(whoami)`,
  после этого — новый вход в систему.
- **iTerm2**, если он был запущен во время установки: Settings → Profiles →
  Go Backend → Other Actions… → Set as Default.
- **Перечитать конфиги:** `exec zsh`; в уже запущенном tmux —
  `tmux source-file ~/.tmux.conf`.

## Обновление и откат

```sh
cd ~/.config/dotfiles && git pull && ./install.sh
```

Откат: удалить строки после `# dotfiles` в `~/.zshrc` и `~/.tmux.conf`,
`git config --global --unset include.path '~/.config/dotfiles/git/gitconfig'`,
удалить ссылки из таблицы выше и вернуть файлы из
`~/.local/state/dotfiles/backup-*`.

## Шпаргалка

### tmux (prefix — `Ctrl-b`)

| Клавиши | Действие |
|---|---|
| `prefix f` | проекты (на весь экран): открытые сессии `●`, сессии прошлого запуска `○` и каталоги; Enter — перейти, восстановить из снимка или создать через `dev`, Ctrl-X — закрыть сессию |
| `prefix g` | lazygit в каталоге текущей панели |
| `prefix G` | изменения и история git (на весь экран, только просмотр): `Alt-c` — changes / staged / log / branch, `Alt-k` — delta / difftastic / git, Enter — целиком в пейджере (ниже) |
| `prefix i` | документация проекта (на весь экран): README и `docs/`, контракты (`.proto`, OpenAPI) и каждый их `rpc` с готовым запросом grpcurl, Go-пакеты (`go doc`), шпаргалка клавиш; Enter — читать целиком (у `rpc` — набрать запрос в окно `rpc`), `Ctrl-y` — скопировать запрос, `q` — назад к списку, Esc — закрыть |
| `prefix t` | дедлайны: обзор с прогрессом; цифра — удалить |
| `prefix s` | дерево сессий и окон |
| `prefix 1..9` | окно по номеру |
| `prefix c` / `\|` / `-` | новое окно / split вбок / split вниз — в каталоге панели |
| `prefix h j k l` | между панелями |
| `prefix z` | развернуть панель (в статус-баре — `zoom`) |
| `prefix [` | copy mode: `v` выделить, `y` скопировать в системный буфер |
| `prefix r` | перечитать конфиг |
| `prefix d` | отключиться; процессы продолжают работать |

Статус-бар: имя сессии жёлтое — нажат prefix, сиреневое — copy mode. У
фоновых окон: `●` команда идёт, `✓` / `✗` — результат (гаснет при входе в
окно). Команда дольше 10 с звонит bell. Справа: git каталога активной
панели — ветка со знаками промпта (`main*+`: `*` незакоммиченное, `+` в
индексе), `↑2 ↓1` — впереди и позади upstream, когда не ноль, в linked
worktree ветка пишется как `@TASK-123`; `⚠` — проблема окружения проекта
(`dev -c`), плашки дедлайнов, время.

### dev — сессия проекта

```sh
dev                    # сессия текущего проекта (корень: go.work → go.mod → .git)
dev backend frontend   # монорепо: окна backend/editor, backend/tests, …
dev -b TASK-123        # сессия под ветку в отдельном git worktree
dev -k                 # закрыть сессию (чистый worktree удаляется)
dev -c                 # проверка: docker, compose, порты, Go toolchain, GOPROXY
dev -w shop            # открыть все проекты набора ~/.config/dev/sets/shop; dev -w — список наборов
dev -W shop            # записать открытые dev-сессии в набор shop
dev -r                 # после перезагрузки: поднять сессии из снимка (все или dev -r имя …)
dev -s                 # снимок сессий вручную; обычно его пишут хуки tmux
```

Окна по умолчанию: `editor` (`nvim .`), `server` (набрано `devlog make run`),
`tests` (сюда отправляет тесты `Space gt`), `infra` (набрано `make up`),
`shell` (`DEV_SHELL=0` — без него). Своя раскладка —
`~/.config/dev/<проект>.zsh`:

```zsh
win editor -x 'nvim .'               # -x — запустить сразу
win server    'devlog make run'      # без -x — набрано, ждёт Enter
pane          'devlog make worker'   # панель под предыдущей
win tests                            # пусто: сюда шлёт тесты Space gt
win infra  -x 'make up'
```

`devlog команда` показывает JSON-логи (slog, zap) одной строкой на запись и
сохраняет сырой вывод в `~/.cache/dev/<сессия>/`. Где искать проекты для
`prefix f` — `DEV_PROJECT_ROOTS` (по умолчанию `~/workspace ~/Projects`).

**Наборы проектов (`dev -w`).** Файл `~/.config/dev/sets/<набор>`: по
строке на проект — каталог и опции `dev` (`~/workspace/shop -b TASK-123`,
`~/workspace/mono backend frontend`), `#` — комментарий. `dev -w набор`
открывает каждую сессию через `dev` и переходит в первую; `dev -W набор`
записывает открытые dev-сессии (worktree задачи — как основной репозиторий
с `-b ветка`).

**После перезагрузки (`dev -r`).** Хуки tmux после каждого изменения окон
и панелей (создание, закрытие, раскладка, переход, отключение клиента)
пишут снимок сессий в `~/.local/state/dev/sessions`: окна с раскладками,
панели с каталогами и программами, опции `dev`. `dev -r` поднимает
сессии, которых нет: dev-сессия — через `dev` в своём корне (раскладка и
набранные команды как обычно, worktree задачи остаётся на диске), затем
окна, добавленные руками (`prefix c`, split), в их каталогах; сессия,
созданная не через `dev`, — как была. Пустые панели — шеллы, nvim
запускается там, где работал. Снаружи tmux в конце — подключение к
последней посещённой сессии. Сессии снимка видны и в `prefix f` как `○`:
Enter восстанавливает одну. Автоматически при старте сервера ничего не
восстанавливается. Первый снимок нового сервера переносит сессии прежнего
как ожидающие восстановления; те, что так и не были подняты, пропадают
при следующем запуске сервера. Сессия, закрытая руками (`dev -k`, `exit`),
из снимка уходит сразу.

**Подсмотр (`gp` / `gP` / `gI`).** Окно появляется рядом с курсором и
закрывается, как только курсор сдвинется. Та же клавиша ещё раз — войти в
окно; внутри `gp` / `gP` / `gI` на любом имени показывают следующий уровень
в том же окне, `Backspace` — назад, так цепочка «хендлер → сервис →
репозиторий» читается, не уходя с места. Enter открывает строку под
курсором (`Ctrl-o` вернёт), `q` закрывает. `gI` на вызове через интерфейс
показывает реализацию: моки и тестовые типы откладываются, если настоящая
реализация одна (в заголовке — сколько отложено), несколько настоящих —
список с превью.

**Движение по коду.** Два слоя поверх обычных `w` / `f` / `/`, оба по
дереву Tree-sitter, не по тексту: прыжки по ключевым словам и ход по
дереву. Каждый прыжок берёт счётчик (`3]e`), работает в Visual и после
оператора (`v]m` выделить до следующего метода, `d]R` удалить до return)
и кладёт прошлое место в jump list — `Ctrl-o` возвращает. Курсор встаёт
на первый символ оператора или объявления.

*По ключевым словам Go (`]x` / `[x`).* Вперёд `]`, назад `[`:

| Клавиша | Куда |
|---|---|
| `]f` / `]F` | функция, метод или замыкание / его конец |
| `]m` | метод |
| `]s` / `]i` | struct или interface / только interface |
| `]v` | `var` или `const` уровня файла |
| `]T` | тестовая функция `func Test…` |
| `]e` | `if err != nil` (любой `if`, где в условии есть `err`) |
| `]R` | `return` |
| `]g` / `]G` | `go` (горутина) / `defer` |
| `]l` | цикл `for` |
| `]w` / `]k` | `switch` или `select` / ветка `case` |
| `]a` | параметр |

*По дереву (`Alt` + `hjkl`).* `Alt-j` / `Alt-k` — следующий и предыдущий
узел того же уровня: от оператора к оператору в теле, от метода к методу
в файле, от поля к полю в структуре; из середины строки берётся оператор
этой строки, так что `v, err := f()` — один шаг, а не три. `Alt-h` —
вверх: сначала начало узла под курсором, потом его родитель
(`nil` → условие → `if` → тело → метод). `Alt-l` — вниз в первый
дочерний узел (из `if` в условие, из тела в первый оператор). `[S` / `]S`
— начало и конец объявления вокруг курсора: функции, метода, типа или
замыкания; `2[S` — объявление уровнем выше (из замыкания в функцию).
Работает в любом языке с парсером; в Go список операторов внутри
`{ }` прозрачен, иначе каждый блок был бы лишним шагом.

*Контракты (`.proto`).* По дереву контракта (парсер Tree-sitter для
proto): `]p` / `[p` — `rpc`, `]M` / `[M` — `message`, `]s` / `[s` —
`message` или `enum`; `Alt` + `hjkl` и `[S` / `]S` работают и тут
(из `rpc` вверх в `service`, `[S` — начало сообщения вокруг курсора).
Подсветка и свёртки `.proto` тоже от парсера.

Узлы перечислены в `nvim/after/queries/go/moves.scm` и
`proto/moves.scm`, клавиши — таблицами в `init.lua`; добавить своё
ключевое слово — строка там и строка здесь. Движение по дереву —
`lua/code_nav.lua`.

**Поля структуры в `K`.** На переменной, параметре или поле, тип которых —
структура (или указатель, срез, массив, канал из них), под обычной
документацией gopls видно объявление этой структуры и всех типов проекта,
которые встречаются в её полях, вглубь: `Order` → `Customer`, `Item` →
`Money`, `Address`. Каждый тип — один раз, в порядке полей, так что
рекурсивный тип не зацикливается; комментарии и теги полей остаются. Типы
не из проекта (`time.Time`, зависимости, `vendor/`) остаются именами,
интерфейсы показываются, но внутрь не раскрываются. У сгенерированных
структур (сообщения protobuf) убраны служебные поля (`state`, `sizeCache`,
`unknownFields`) и теги. На имени самого типа gopls уже показывает его
поля — добавляются типы этих полей. Больше 15 типов не показывается
(`// … more types`); `K` ещё раз — войти в окно и листать.

**Весь экран.** Все окна поиска (`Space f`, `Space /`, `Space sS`, `grr`,
TODO, буферы, диагностики) и графы (`gre` / `grc` / `gro`, `Space sQ`,
`Space ct`) открываются на весь экран; `F2` в окне поиска уменьшает его и
возвращает. Маленькими остаются только короткие списки без превью
(категории, виды) и подсмотр `gp` / `gP` / `gI` с `K` — они у курсора.

**Нормальный режим в окнах поиска.** В любом окне fzf `Esc` выходит из
набора в режим с `·N` в приглашении: `j` / `k` ходят по списку, `g` —
первая строка, `l` или `Enter` открывает, `q` или `Esc` закрывает, `i`
возвращает набор, запрос при этом остаётся. Списки без запроса (`Space
f`, символы файла `Space ss`, буферы `Space b`, закреплённые `Space p`,
`Space ,`, `grr`) открываются сразу в этом режиме, живые поиски (`Space
/`, `Space sS`, `Space ?`) — в наборе. Состояние живёт в приглашении
(fzf сам ничего не помнит), клавиши — строки shell для `transform`
(`lua/picker_mode.lua`), поэтому задержек нет.

**Панель файлов (`Space e`).** Дерево проекта слева шириной 36 колонок,
открывается на текущем файле и следует за ним при переходах. `←` / `→`
(или `h` / `l`) сворачивают и разворачивают папку, `Enter` открывает файл,
`s` / `S` — в вертикальном / горизонтальном сплите, `.` делает папку корнем,
`Backspace` поднимает корень на уровень выше, `H` показывает и прячет
игнорируемые файлы, `a` / `r` / `d` создают, переименовывают и удаляют,
`y` / `x` / `p` копируют, вырезают и вставляют, `/` фильтрует дерево по
набранному (`Enter` оставляет фильтр), `Ctrl-h` снимает фильтр — и в
окне набора, и потом в дереве; `?` — все клавиши.
Справа от имени — буква git-статуса (`M`, `A`, `?`). `Space` внутри панели
остаётся лидером. Файлы показаны со значками по типу (nvim-web-devicons):
они же в `Space f`, в поиске текста и в списке буферов. Значкам нужен
шрифт Nerd Font — `JetBrainsMono NF` из `Brewfile` стоит в профиле iTerm2
«Go Backend». Без него вместо значков в `Space f` — обычные символы
Юникода, а в панели — знаки `?`.

**Окна.** Все всплывающие окна (документация `K`, подсмотр, дополнение,
диагностика) в одинаковой скруглённой рамке; знаки диагностики в колонке
слева — глифы Nerd Font по важности.

**Вкладки.** Открытые буферы — вкладками вверху со значком, точкой у
несохранённого и числом ошибок gopls; появляются, когда файлов больше
одного, панель `Space e` сдвигает их вправо. Имя файла внизу не
повторяется: в строке состояния только флаги и позиция, путь и место
курсора — в строке «где я» над окном.

**Подсказка клавиш.** После `Space`, `g`, `]`, `[` и других префиксов
через 0,4 с появляется список продолжений с описаниями (which-key).

**Дерево файлов (`Space f`).** Слева файлы, справа превью. Пока запрос
пуст, файлы показаны папками, свёрнутыми до одной строки с числом файлов,
поэтому стрелки идут от папки к папке, а не через каждый файл:

| Клавиши | Действие |
|---|---|
| `→` | раскрыть папку; на раскрытой — к первому файлу в ней |
| `←` | свернуть папку; на файле — перейти к его папке |
| `Enter` | открыть файл; на папке — раскрыть или свернуть |
| `Alt-/` | поиск текста внутри папки под курсором |
| `i`, затем текст | обычный нечёткий поиск по всем файлам (`Files>`); стёр запрос — снова дерево (`Tree>`) в том же виде; `Esc` — назад в нормальный режим |

Папки идут первыми; цепочка папок с единственной папкой внутри — одна
строка (`pkg/api/order/v1/`). У папки Go-пакета рядом — первая фраза его
комментария (`order/ 13 · manages purchases.` из `// Package order
manages purchases.`, `doc.go` главнее). Сверху — группы: ** pinned**
(закреплённые, с номерами для `Alt-1…9`), ** changed** (изменённые
относительно HEAD по `git status`, с буквой статуса: `M` изменён, `A` в
индексе, `?` новый) и ** recent** (недавно открытые, без текущего).
`changed` и `recent` свёрнуты до одной строки, `pinned` раскрыта; курсор
при открытии стоит на первом закреплённом, а без закреплённых — на
текущем файле в дереве. Изменённые файлы и в дереве, и в поиске окрашены:
новые зелёным, изменённые синим. `←` на файле из группы показывает его в
дереве; раскрытая или свёрнутая руками группа остаётся такой до конца
сеанса. Папка текущего файла раскрыта. Превью папки — комментарий пакета, его экспортируемый API
(типы с методами, функции, константы, переменные — через AST-хелпер) и
что внутри неё (с учётом категории). `Alt-c` — категория, `Alt-i` /
`Alt-h` — показывать игнорируемые / скрытые файлы или нет, `Alt-/` —
поиск текста внутри папки под курсором.

Файлы отмечены по типу, цвет из темы, метки — обычный Юникод: `▪` Go,
зелёная у `_test.go`; `▫` сгенерированный Go (`*.pb.go`, `*.pb.*.go`,
моки, `*_gen.go`, `*.gen.go`, `*_string.go`, `*.sql.go`,
`zz_generated*`) — притушен вместе с именем; `◇` `.proto`; `▤` `.sql`;
`≡` markdown; `∷` yaml / json / toml / env; `$` Makefile, Dockerfile,
compose, `*.sh`; `▣` `go.mod` / `go.sum` / `go.work`. Тип определяется по
имени файла; те же метки — в поиске `Files>`, в группах и в превью папки.

**Закреплённые файлы (`Space p`).** Короткий список файлов задачи:
`Space p` закрепляет текущий файл (номер — следующий) или открепляет его,
`Alt-1` … `Alt-9` открывают по номеру, `Space P` — список с превью:
`Ctrl-x` открепить, `Alt-↑` / `Alt-↓` поменять порядок (а с ним номера).
Список свой у каждого проекта (каталог, где запущен `nvim .`; у worktree
от `dev -b` — свой) и сохраняется между запусками. В строке «где я» у
закреплённого файла — его номер: `◆2 internal/order/service.go › …`.

**Покрытие (`Space gc`).** Запускает `go test -coverprofile` пакета
текущего файла из корня модуля, в уведомлении — процент операторов и
число строк файла, которые тест прошёл и не прошёл. Полоски рисуются во
всех открытых файлах пакета и в тех, что откроются позже, до следующего
запуска или `Space gC`. Блок у Go начинается с первого оператора функции,
поэтому строка сигнатуры без полоски.

**Реализовать интерфейс (`Space gm`).** Курсор на `type PgRepo struct`,
`Space gm` показывает интерфейсы проекта (AST-хелпер); после выбора под
типом появляется `var _ Repository = (*PgRepo)(nil)`, и gopls дописывает
каждый недостающий метод с сигнатурой, doc-комментарием и телом
`panic("unimplemented")`. Утверждение остаётся как документированное
обещание.
Интерфейс чужого пакета — по имени: `:GoImpl io.Reader`, импорт добавит
gopls.

**Контракты против main (`Space cp`).** Рабочее дерево сравнивается с
merge-base `HEAD` и `origin/main` (или `main`, `master`; без них —
`HEAD~`) по `.proto`, включая незакоммиченные и новые файлы. В списке —
каждое изменённое объявление: ✗ ломающие первыми (удалённый rpc, message,
поле или значение enum; поле с новым номером или типом; rpc с другим
запросом или ответом; удалённый сервис), затем `!` переименованное поле с
тем же номером (провод цел, JSON и Go-код ломаются), `~` правки строки
объявления и `+` добавленное. Enter — на строку в рабочем файле; у
удалённого — на начало родителя. Проверка текстовая, по строкам
объявлений, без компилятора proto.

**Rpc во всех репозиториях (`grP`).** Сервис и rpc берутся из строки
`rpc` в `.proto`, из сгенерированного кода, из хендлера (через интерфейс,
который он реализует) или из вызова клиента `client.PlaceOrder(ctx, …)`
(через определение, как `grp`). Затем `rg` по репозиториям `Space ?`:
**handler** — `func (s *Server) PlaceOrder(ctx …)`, это сервис-владелец;
**contract** — `rpc PlaceOrder(`; **call** — `.PlaceOrder(ctx`; **test**.
Сгенерированный код, моки, vendor и worktree пропускаются.

**Путь ошибки (`Space ce`).** Курсор внутри функции; дерево её вызывающих
(gopls, как `gre`), и у каждой пометка по тексту тела: `→ gRPC NotFound,
Internal` (`status.Error` / `status.Errorf` / `status.New`, `connect.NewError`
— ветка на этом кончается, ошибка стала статусом), `wraps "place order"`
(`fmt.Errorf("…: %w")`, текст показан), `passes up` (`return …, err`),
`logs, stops`, `panics`, `handles`; `· checks` — есть `errors.Is` /
`errors.As`. Корень показывает, из чего сделаны его собственные ошибки.
Пометка — подсказка по исходнику, не по типам; справа превью кода, Enter —
место вызова, `d` — объявление.

**proto ↔ Go (`grp`).** В `.proto`:

| Курсор на | Куда |
|---|---|
| `rpc CreateOrder` | в реализацию — метод хендлера; сгенерированный `Unimplemented…` и моки откладываются; несколько — список с превью; ещё не реализован — метод интерфейса `…Server` |
| `service OrderService` | в типы, которые его реализуют |
| `message` / вложенный `message` / поле | в сгенерированную структуру (`Order_Item`) / в её поле (`user_id` → `UserId`) |
| `enum` | в сгенерированный тип |

В Go обратно в `.proto`: с метода хендлера — в его `rpc`; с типа
сообщения, его поля или геттера (`GetUserId`) — в `message` / поле; с
константы enum — в `enum`; с вызова клиента (`c.CreateOrder(…)`) — в
`rpc`; в сгенерированном файле — с того, что под курсором. `.proto`
находится по строке `// source:` сгенерированного файла; реализации ищет
gopls (если открыт только `.proto`, gopls запускается сам). `Ctrl-o`
возвращает.

**Категории поиска (`Alt-c`).** В проекте с десятками gRPC-контрактов
сгенерированный код забивает выдачу. Поиск файлов (`Space f` / `Space F`),
текста (`Space /`, `Space *`) и символов (`Space sS`) открывается на всём
проекте; `Alt-c` прямо в окне поиска показывает категории с числом файлов:

| Категория | Что в ней |
|---|---|
| `all` | весь проект, как раньше |
| `rpc` | контракты и код из них: `.proto`, `*.pb.go` (и `*_grpc.pb.go`), `*.pb.*.go` (gateway, validate), connect, twirp, swagger, конфиги buf |
| `tests` | `*_test.go`, моки и фейки (`*mock*.go`, `mocks/`, `fakes/`), `testdata/`, `test/`, `tests/` |
| `internal` | `internal/` на любой глубине — без `rpc` и `tests` |
| `internal/order/` … | одна папка `internal` со всеми вложенными; в списке — каждая папка |
| `api/` … | любая другая папка целиком — через `Alt-/` в дереве `Space f`; пока она выбрана, есть и в списке `Alt-c` |

Набор текста фильтрует список, Enter переключает категорию, набранный
запрос остаётся; Esc возвращает поиск как был. Категория видна в
заголовке окна (` files · internal/order/ `). Файлы, игнорируемые git,
остаются скрытыми и в категориях (`Space F` показывает и их).

Символы ищет gopls, а он отдаёт не больше 100 на запрос — сгенерированный
код может занять их все. Поэтому для `internal` и его папок запрос
сужается на стороне gopls по пути пакета, а для `tests` дополнительно
спрашиваются `Test…` и моки; на пустой запрос `internal/order/` покажет
символы этой папки.

**Тот же домен в других слоях (`Space ,`).** Для `internal/app/order/handler.go`
домен — папка `order`: список на весь экран показывает файлы всех других
папок с таким именем (`internal/service/order/`, `internal/repo/order/`,
`api/order/v1/` …) с метками дерева, а ниже — файлы с тем же именем в
других пакетах (`· same name`: тот же слой в других доменах). Имена папок,
которые говорят о структуре, а не о домене (`v1`, `internal`, `pkg`,
`cmd`, `api`, `handler`, `service`, `repository` …), пропускаются вверх
по пути, так что для `api/order/v1/order.proto` домен тоже `order`; если
все папки такие, доменом служит имя файла.

**Символы по видам (`Alt-k` в `Space sS`).** Список видов с числом
объявлений в текущей категории: `struct`, `interface`, `type`, `func`,
`method`, `const`, `var`. Выбранный вид — все такие объявления верхнего
уровня (`▦ struct Order`, `ƒ method (*Service) Create`) с превью; набор
текста фильтрует. Их собирает AST-хелпер, а не gopls: без предела в 100,
пустой запрос показывает всё, и сгенерированный код (игнорируемый git) тоже
виден, как его видит компилятор. Вид и категория сочетаются: `Alt-c` →
`internal/order/`, `Alt-k` → `struct` — все структуры этой папки. Вид
`all` — снова живой поиск gopls. Файлы разбираются параллельно и
запоминаются до изменения: 2000 файлов — около полсекунды в первый раз.

**SQL (`Space sQ`).** Все запросы проекта в одном дереве, справа — код
выбранного:

- строки Go, которые начинаются с запроса (`SELECT … FROM`, `INSERT INTO`,
  `UPDATE x SET`, `DELETE FROM`, `WITH x AS (`, DDL); склейки через `+` и
  строковые константы пакета подставляются;
- цепочки squirrel: `sq.Select(…).From("orders o").Join(…)`,
  `sq.Insert(ordersTable)`, `psql.Update(…)`;
- `.sql`: миграции goose (`↓` — секция Down) и запросы sqlc (`-- name:`).

Группы — таблицы (запрос с JOIN попадает в каждую); `Tab` переключает на
виды запросов (`SELECT`, `INSERT`, …) и на файлы. Чтения — синим, записи —
жёлтым, схема — фиолетовым. Enter на запросе открывает его, на группе —
сворачивает и разворачивает (`zM` / `zR` — все), `r` — пересканировать.
Превью группы-таблицы — её `CREATE TABLE` из миграции. Сгенерированный код
(`// Code generated … DO NOT EDIT.`) и `vendor/` пропускаются.

SQL подсвечивается и в `.sql`, и внутри строк Go — по тем же правилам, так
что `"update order: %w"` остаётся обычным текстом. Теги TODO / FIXME / HACK
в комментариях выделены цветом.

**Markdown.** README, документы и всплывающая документация `K` видны
оформленными, как в просмотрщике: заголовки — цветными полосами без `#`,
код — на фоне, таблицы — в рамках, `- [x]` — галочками, у ссылок — только
текст. Строка под курсором и режим вставки показывают сырой текст, чтобы
его было удобно править; в окне документации `prefix i` (nvim только для
чтения) оформлена и она. `Space m` — сырой текст всего файла и обратно.
Значки — обычные символы Юникода; формулы LaTeX не рисуются (для них
нужна внешняя программа).

**Строка «где я».** Над каждым окном с файлом: путь от корня проекта и то,
где стоит курсор — `internal/order/service.go › (*Service) PlaceOrder › func`
или `model.go › Order › Total`. Строится по дереву Tree-sitter, gopls не
нагружает; в больших файлах — только путь.

**Действия gopls (`gra`).** Что gopls предлагает в типичных местах:

| Где | Действие |
|---|---|
| выделены строки | Extract function |
| выделено выражение | Extract variable |
| на вызове функции | Inline call |
| на литерале `Order{}` | Fill Order — заполнить все поля |
| на имени функции | Add test for F — табличный тест в `_test.go`; Extract declarations to new file |
| на типе, который не реализует интерфейс (`var _ I = (*T)(nil)`) | Declare missing methods |
| на поле структуры | Add struct tags / Remove struct tags |
| на строковом литерале | Convert to raw string literal |

`Browse documentation / assembly / free symbols` открывают страницу gopls
в браузере.

**Замена текста по проекту** (комментарии, строки, SQL — то, что не
переименовать по смыслу): `Space /` → `Alt-a` (выбрать всё) → `Alt-q` (в
quickfix) → `:cdo s/старое/новое/gc | update`.

**Дерево правок.** Корни — Go-объявления, изменённые относительно `HEAD`
(`git diff HEAD` и неотслеживаемые `.go`). Без git — объявление под
курсором. Для каждого корня gopls находит:

- кто от него зависит: `caller`, `ref`, `test`, `impl`;
- что он использует: `calls`, `type`, `value`, `field`, `iface`.

В окне дерева Enter переходит к месту использования, `d` — к объявлению.
Символ `↑` означает, что узел уже есть выше по ветке.

Команды:

- `:ChangeTree!` — открыть последнее дерево без пересборки;
- `:ChangeTreeText`, `:ChangeTreeLedger`, `:ChangeTreeTrace`, `:ChangeTreeIndex` —
  граф текстом, разбор идентификаторов, запросы к gopls, список изменённых объявлений.

### git

- `git diff`, `show`, `log -p` и `add -p` выводятся через delta; `n` / `N` — следующий / предыдущий файл.
- `git ds` — две колонки.
- `git dft`, `git dshow <sha>`, `git dlog` — diff по синтаксису (difftastic).
- lazygit — `prefix g`; `|` переключает отображение diff: delta → difftastic → git.

**Просмотр (`prefix G`).** Репозиторий каталога текущей панели (worktree
учитывается) на весь экран: слева список, справа превью. `Alt-c`
переключает режим по кругу: `changes` — рабочее дерево к HEAD с двумя
колонками статуса, как у `git status --short` (индекс и рабочее дерево:
`M`, `A`, `D`, `R`, `??`); `staged` — только индекс; `log` — коммиты
ветки; `branch` — коммиты, которых нет в `origin/HEAD` (без origin —
относительно `main` / `master`), то есть будущий PR. `Alt-k` — рендерер:
delta, difftastic, git. Enter показывает файл или коммит целиком в
пейджере (`n` / `N` — по файлам, `q` — назад к списку), `Ctrl-d` /
`Ctrl-u` листают превью, Esc закрывает. Режим и рендерер видны в
промпте (`changes · delta ›`); если изменений нет, окно открывается сразу
на `log`. Действия git (stage, commit, rebase) остаются в командной строке
и lazygit.

### gRPC и HTTP-запросы

Оба инструмента под MIT и ходят в сеть только к серверу запроса (ни
телеметрии, ни проверки обновлений):

```sh
grpcurl -plaintext localhost:8082 list                    # сервисы (server reflection)
grpcurl -plaintext localhost:8082 describe order.v1.Order # сообщение; -msg-template — его заготовка
grpcurl -plaintext -d '{"user_id": 1}' localhost:8082 order.v1.OrderService/CreateOrder
grpcurl -plaintext -import-path api -proto order/v1/order.proto -d @ localhost:8082 … <<<'{"id": 1}'  # без reflection

xh :8080/v1/orders user_id=1          # POST с JSON (ключ=значение), ответ подсвечен
xh GET :8080/v1/orders/1 Authorization:"Bearer $TOKEN"
xh --offline :8080/v1/orders user_id=1   # показать запрос, не отправляя; --curl — тот же запрос как curl
```

**Заготовка запроса (`grq`, `prefix i`).** В `.proto` на строке `rpc`
(или внутри его блока), а в Go на методе хендлера или вызове клиента
`grq` собирает строку

```sh
grpcurl -plaintext -d '{"user_id": 0, "items": [{"sku": "", "count": 0}]}' localhost:8082 order.v1.OrderService/CreateOrder
```

и набирает её в окно `rpc` сессии tmux (создаётся при первом запросе, в
монорепо — `backend/rpc`, как `tests` у `Space gt`), не выполняя: окно
показывается, строку можно поправить (`Ctrl-X Ctrl-E` — в nvim) и
запустить Enter. Вне tmux строка попадает в буфер обмена. JSON — заготовка
сообщения запроса по `.proto` проекта: каждое поле с образцом значения
(строки `""`, числа `0`, `bool` `false`, enum — первое настоящее значение,
`repeated` — один элемент, `map` — одна запись, `oneof` — первый вариант,
вложенные сообщения — рекурсивно, в том числе из импортов внутри проекта;
`Timestamp`, `Duration`, обёртки — образцами). Адрес — порт рядом со
словом `grpc` в `.env*`, `config*.y*ml`, `values*.y*ml`, compose и
`Makefile`, иначе `localhost:8080`. Если в проекте нет
`reflection.Register`, добавляются `-import-path` и `-proto`. В `prefix i`
каждый `rpc` контрактов — отдельный пункт: в превью его объявление,
сообщение запроса и команда; Enter набирает её в то же окно `rpc`,
`Ctrl-y` копирует.

### zsh

|---|---|
| `Ctrl-R` / `Ctrl-T` / `Alt-C` | fzf: история, файлы, перейти в каталог |
